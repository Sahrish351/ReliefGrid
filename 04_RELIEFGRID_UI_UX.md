# RELIEFGRID AI — UI/UX, Visual Design & Image Direction

## 1. Design Objective

Create a visually exceptional, polished, premium humanitarian technology platform.

The UI must feel:
- trustworthy
- modern
- human
- intelligent
- operational
- calm under pressure
- premium
- accessible

It must NOT look like:
- a generic Tailwind template
- a basic student CRUD application
- a dark-only admin dashboard
- an AI chatbot wrapper
- a collection of repetitive cards

## 2. Visual Identity

Primary:
- Warm white
- Deep navy
- Charcoal
- Emergency red
- Amber
- Soft green
- Cool gray

Suggested palette:
- Background: #F7F8FA
- Surface: #FFFFFF
- Text: #101828
- Muted text: #667085
- Navy: #102A43
- Emergency red: #D92D20
- Warning amber: #F79009
- Success green: #039855
- Border: #E4E7EC

Do not overuse red. Red is reserved for critical emergency states.

## 3. Typography

Use:
- Headings: Manrope or Plus Jakarta Sans
- Body/UI: Inter

Hero headings should be large and responsive using clamp().

Maintain strong hierarchy.

## 4. General UI Rules

- Generous whitespace.
- 12–20px corner radii depending on component.
- Soft shadows.
- Thin borders.
- Avoid excessive glassmorphism.
- Avoid excessive gradients.
- Avoid every component being a pill.
- Use iconography consistently.
- Use accessible contrast.
- Provide hover/focus/active states.
- Provide skeleton/loading states.
- Provide empty states.
- Provide error states.
- Provide success states.

## 5. Image Strategy

Images are a major part of the public website.

Use high-quality, relevant humanitarian/emergency photography.

Do NOT use:
- random unrelated stock photos
- broken URLs
- fake image URLs
- repetitive images in every card
- inappropriate disaster gore
- graphic injury images
- sensational tragedy imagery

Use:
- flood rescue teams
- emergency response vehicles
- humanitarian volunteers
- relief distribution
- shelters
- emergency medical teams
- community preparedness
- rescue coordination
- aerial disaster context
- volunteers carrying supplies

Images should feel respectful and human.

Use contextual image crops, rounded containers, editorial split layouts, full-width hero imagery, and image overlays.

If external image URLs are used, they must be valid and reliable. Never invent URLs. Prefer a centralized image configuration so images can be replaced safely.

## 19. Animations

Use subtle, purposeful motion:
- page reveal
- card hover
- number count-up
- status transitions
- agent processing steps
- map marker pulse for critical incidents
- timeline progress
- skeleton loading

Do not over-animate.

Respect reduced-motion preferences.

## 20. Responsive Design

Mobile must be a first-class experience.

Citizen emergency reporting must be especially mobile-friendly.

Command center on tablet:
- map
- priority queue
- collapsible panels.

On mobile:
- bottom navigation where appropriate.
- stacked cards.
- sticky emergency action.
- simplified maps.

## 21. Accessibility

- Semantic HTML.
- Keyboard navigation.
- Visible focus states.
- Alt text.
- Color is never the only indicator.
- Good contrast.
- Form labels.
- Error messages.
- Reduced motion support.

## 22. Empty/Error/Loading States

Examples:

No active emergencies:
"You're all clear right now."

No resources:
"No available units match this request. The coordinator has been notified."

AI unavailable:
"AI analysis is temporarily unavailable. Your report has still been safely recorded."

Never show technical stack traces to users.

## 25. Quality Bar

Every page should feel intentionally designed.

Avoid:
- repetitive identical cards
- excessive rounded rectangles
- placeholder copy
- lorem ipsum
- fake testimonials
- fake partner logos
- fake statistics presented as real
- broken images
- excessive gradients
- generic dashboard templates

Use synthetic/demo labels wherever appropriate.
